# rvdbg User Guide

[中文](../cn/README.md)

`rvdbg` uses one `rvdbg.toml` to flash, debug and inspect rustvisor boards. With a Lauterbach probe it uses TRACE32 PowerView; with StellarLINK it runs `openocd-stellar` as a separate process. Build firmware with your project's own build system: rvdbg deploys existing images and helps inspect the target.

This guide covers Apple Silicon macOS and Linux x86_64/aarch64 hosts. The board defaults generated by `rvdbg init` target SR6P6. Before using another board, check scripts, core names, memory access ports and OTP ranges.

## Backend differences

| Capability | TRACE32 | StellarLINK / OpenOCD |
| --- | --- | --- |
| Flash, verify, status, halt and resume | Supported | Supported |
| IDEs | VS Code and RustRover/LSP4IJ over DAP | VS Code/Cortex-Debug and GDB |
| Ordinary RAM, RTT and FDX | Runtime access through `AD:` | Runtime access through MEM-AP |
| Debug symbols | `rvdbg load` | GDB reads the ELF |
| PER register names | `reg`, `watch` | Use addresses or check files instead |
| PRACTICE | `eval`, `cmd`, `do` | Unsupported |
| Trace export | `trace`, `fault --trace` | Unsupported |
| Clock diagram | `clock --html` | Text/JSON tree only |

Shared command names do not imply that every option works on both backends. See [configuration](configuration.md) for selection and individual task pages for restrictions.

## Understand what an operation changes

Inspection commands such as `status`, `mem`, `fault`, `verify` and `check` without `--halt` do not automatically reset or halt the target to obtain a value. Some register reads will therefore fail. Distinguish ordinary RAM from MMIO with read side effects; see [inspection](inspection.md).

`flash` writes Flash and resets the target; `reset` resets and halts it. `halt`, `go` and `run-until` change execution state. `load` loads symbols and resumes when necessary. IDE connection can also execute board reset hooks; see [debugging](debugging.md).

`ram --write` changes target RAM. FDX sends can trigger firmware actions. `cmd` and `do` depend on the PRACTICE content and can perform arbitrary target operations.

Use `rvdbg --help` and `rvdbg <command> --help` for full arguments. This guide explains workflows and interpretation; consult your installed version's help and `rvdbg init` output for defaults. See [maintaining this guide](writing.md) for local previews and link conventions.
